# Repository Guidelines

## Project Overview

WelkinAdmin is a Vue 3 enterprise admin platform forked from [soybean-admin](https://github.com/soybeanjs/soybean-admin) under MIT. The current `example` branch is the full-featured variant: system management, monitoring, message/user-center pages, plugin demos, Pro Naive UI examples, and dynamic or static permission routing.

Technology stack: Vue 3, TypeScript, Vite, Pinia, Vue Router, Naive UI, UnoCSS, vue-i18n, Alova, and local/mock HTTP middleware. The repository is a pnpm workspace monorepo.

## Architecture & Data Flow

- **Startup**: `src/main.ts` initializes loading, progress, Iconify, Day.js, Pinia, Router, Pro Naive UI, i18n, update notification, and the root validator before mounting `src/App.vue`.
- **Root shell**: `src/App.vue` provides Naive UI theme/locale/date-locale configuration, the global `AppProvider`, `RouterView`, and optional watermark. Theme and locale state come from Pinia and local storage.
- **Routing**: `src/router/index.ts` creates the router. `src/router/guard/` initializes constant routes, authenticates the token, loads user routes, handles redirects/404/403, and coordinates tab state. `src/router/elegant/` is generated by Elegant Router from `src/views/`; `src/router/routes/` contains built-in/custom route definitions.
- **Permission routes**: `VITE_AUTH_ROUTE_MODE=dynamic` is the default. `src/store/modules/route/` fetches backend menus through `src/service/api/route.ts`, converts backend menu records to route metadata, installs authorized routes, and derives menus/breadcrumbs/search/cache state. Static mode uses `src/router/routes/index.ts` and role filtering.
- **Authentication**: `src/store/modules/auth/` owns token/user state and login flows. API functions live in `src/service/api/auth.ts`; tokens are persisted through `src/utils/storage.ts`. Login fetches a token, persists access/refresh tokens, loads user info, then redirects and refreshes tabs.
- **Requests**: `src/service/request/index.ts` creates the shared Alova client using `@sa/alova`. It attaches `Bearer` authorization, treats the configured backend code as success, unwraps `data`, refreshes expired tokens, logs out on configured codes, deduplicates error messages, and rethrows failures. Base URLs/proxy patterns are centralized in `src/utils/service.ts` and `build/config/proxy.ts`.
- **Pages**: `src/views/` contains route pages. Larger management pages use `index.vue` for composition and `modules/` for search forms, drawers, dialogs, and table-specific logic. A representative flow is `src/views/auth/user/index.vue`: search component → paginated remote `NDataTable` → operation drawer/detail drawer → API refresh.
- **Mock flow**: `build/plugins/index.ts` installs `mock/server/plugin.ts`. In test development, local mock middleware handles `/proxy-default/*` before Vite proxy; unmatched requests can fall through to the configured backend. `VITE_MOCK_MODE` supports `hybrid`, `backend`, and `custom` behavior.

## Key Directories

- `src/views/`: route pages; route file names are consumed by Elegant Router.
- `src/components/`: reusable common, advanced table, and custom components.
- `src/layouts/`: base authenticated layout, blank layout, and layout modules.
- `src/router/`: route definitions, guards, and generated Elegant Router output.
- `src/store/modules/`: Pinia setup stores for app, auth, route, theme, tab, and related state.
- `src/service/api/`: typed API functions; `src/service/request/`: Alova instance and auth/error handling.
- `src/typings/api/`: ambient API domain types; `src/typings/app.d.ts`: global app/theme/i18n/service types.
- `src/locales/langs/`: Chinese and English translation schemas; update both languages and the i18n type schema for every new key.
- `src/hooks/`, `src/utils/`, `src/constants/`, `src/enum/`: shared composition utilities, helpers, constants, and IDs/enums.
- `build/`: Vite plugins, Elegant Router integration, UnoCSS integration, proxy, and build-time configuration.
- `packages/`: workspace packages currently named `@sa/*` on `example` (`alova`, `axios`, `color`, `hooks`, `materials`, `scripts`, `uno-preset`, `utils`).
- `mock/`: local development middleware, route handlers, database fixtures, and response helpers.
- `src/mock/`: frontend-local mock handlers used by source modules.
- `scripts/`: application data seed scripts (`seed:dicts`, `seed:menus`).
- `public/`: files copied without bundling.

## Development Commands

```bash
pnpm install
pnpm dev             # test mode, Vite on http://localhost:41527
pnpm dev:prod        # prod-mode development server
pnpm build           # production build
pnpm build:test      # test-mode build
pnpm preview         # preview the built app, port 9725
pnpm typecheck       # vue-tsc --noEmit --skipLibCheck
pnpm lint            # oxlint --fix, then eslint --fix .
pnpm fmt             # oxfmt
pnpm gen-route       # generate Elegant Router files from src/views/
pnpm seed:dicts      # seed dictionary data
```

The bundled `sa` CLI also exposes `pnpm sa cleanup`, `pnpm sa gen-route`, `pnpm sa git-commit`, `pnpm sa release`, and `pnpm sa update-pkg`. `pnpm gen-route` is the normal route-generation command; do not hand-edit `src/router/elegant/routes.ts`, `imports.ts`, or related generated declarations.

## Code Conventions & Common Patterns

- Use strict TypeScript and Composition API with `<script setup>`. Prefer explicit interfaces/types over `any`; API response/domain types belong in `src/typings/api/`.
- Follow the existing SFC pattern: script first, template second, empty or narrowly justified style block. Use PascalCase component tags and `defineOptions({ name: '...' })` where the surrounding module does so.
- Build UI with Naive UI/Pro Naive UI components (`NCard`, `NForm`, `NDataTable`, `NModal`/`NDrawer`, `NButton`, `NPopconfirm`) and project components such as `TableHeaderOperation`, `TableColumnSetting`, `SvgIcon`, and `ButtonIcon`. Do not replace established components with raw form/table controls.
- Use UnoCSS utilities and project shortcuts such as `card-wrapper`; keep custom CSS minimal. `uno.config.ts` defines the `presetWelkinAdmin` preset, `dark:` class mode, theme variables, and shortcuts.
- Management table pages normally combine search state, loading state, remote pagination, checked row keys, a table operation header, and modal/drawer modules. Keep page composition in `index.vue`; move substantial forms and operations into sibling `modules/` files.
- Use Pinia setup stores via `defineStore(SetupStoreId.X, () => { ... })`. Keep cross-store coordination explicit; auth, route, tab, app, and theme stores already form the main state flow.
- Use API functions from `src/service/api/` instead of issuing requests in views. Return typed Alova calls and let the shared request instance handle authorization, success-code unwrapping, token refresh, logout, and error reporting.
- Use `window.$message`/the project message setup for user feedback and preserve loading states around async operations. Do not swallow request errors; the request layer rethrows them after handling global effects.
- Use `$t('...')`/`useI18n` for user-visible text. Add every key to `src/locales/langs/zh-cn.ts`, `src/locales/langs/en-us.ts`, and the `App.I18n.Schema` declaration in `src/typings/app.d.ts`.
- For icons, use verified Iconify names in route metadata or existing local SVG assets; do not invent icon identifiers. Current route metadata is centralized in `build/plugins/router.ts`.
- Keep IDs that may exceed JavaScript safe integer range as strings, matching the system-management API types.
- Use `@/*` for `src/*`, `~/*` for repository-root imports, and `@sa/*` for workspace packages on this branch. Porting from `main` requires rewriting `@welkin/*` versus `@sa/*` imports and reinstalling dependencies after a branch switch.

## Important Files

- `package.json`: scripts, dependencies, engines, and simple-git-hooks.
- `pnpm-workspace.yaml`: `packages/*` workspace and pnpm linking/build policy.
- `src/main.ts`, `src/App.vue`: application entry and global shell.
- `src/router/index.ts`, `src/router/guard/route.ts`, `src/store/modules/route/`: router setup, auth guard, and permission route state.
- `src/store/modules/auth/index.ts`: login, token persistence, user initialization, and logout/reset behavior.
- `src/service/request/index.ts`, `src/service/request/shared.ts`: request success/error/token-refresh contract.
- `src/service/api/`: backend endpoint functions; pair changes with `src/typings/api/` types.
- `src/views/`: page and route source; route generation derives from this tree.
- `build/plugins/router.ts`: generated route metadata, layouts, route-name transforms, and role/menu metadata.
- `vite.config.ts`, `build/plugins/index.ts`, `build/config/proxy.ts`: Vite aliases, server/preview ports, plugins, local mock, and HTTP proxy.
- `.env`, `.env.test`, `.env.prod`: app, route, mock, backend-code, proxy, storage, and build flags. Never commit secrets.

## Runtime/Tooling Preferences

- Required runtime: Node.js `>=20.19.0`; package manager: pnpm `>=10.5.0`. Use pnpm workspace commands, not npm or yarn.
- `package.json` is strict JSON; preserve valid JSON when editing scripts or dependencies.
- Vite aliases are `@` → `src` and `~` → repository root. Dev server binds `0.0.0.0:41527`; preview uses `9725`.
- Test mode uses `.env.test` and the local gateway/mock setup. Production mode uses `.env.prod`; its default service base is `/api`.
- Formatting uses Oxfmt: 120-column width, single quotes, no trailing commas, no parentheses for single arrow parameters. Generated route/type files are excluded from formatting.
- Linting uses Oxlint correctness/suspicious categories plus the Soybean ESLint Vue config. `pnpm lint` fixes files; inspect the diff after running it.
- Workspace packages on this branch are `@sa/*`; stale `node_modules` from `main` can cause missing-package errors after switching branches. Reinstall dependencies if package links are inconsistent.

## Testing & QA

There is no repository test framework or test suite in the current checkout. Use these checks for changes:

1. `pnpm typecheck` for Vue/TypeScript contract errors.
2. `pnpm lint` and `pnpm fmt` for static/style validation; both may rewrite files.
3. `pnpm build` or `pnpm build:test` for bundling and generated-route/import failures.
4. For UI or request changes, run `pnpm dev`, exercise the affected page/API path in the browser, and verify console/network errors and loading/error states.
5. For route changes, run `pnpm gen-route` and review generated output rather than editing generated files directly.

Git hooks enforce `pnpm typecheck && pnpm lint && pnpm fmt && git diff --exit-code` before commit and Conventional Commit syntax through `pnpm sa git-commit-verify`. Use commit subjects such as `fix(auth): handle expired access token`.
